# CheaperGen API

One async REST API for official video and image models. Billing comes from a prepaid USD balance: you pay per second of video or per image, and failed generations are refunded automatically.

- Base URL: `https://cheapergen.com/api/v1`
- Auth: `Authorization: Bearer $CHEAPERGEN_API_KEY` (keys start with `cg_live_`; create one at https://cheapergen.com/dashboard/keys). Read the key from the environment. Never print it, log it or commit it.
- **Prefer the MCP server when it's connected.** Its tools are `list_models`, `get_model`, `quote` (its `balance` says whether the account can pay, and which `add_credits` amount to offer when it can't), `generate` (with `wait_seconds`, a `max_cost_usd` budget guard and `allow_fallback_price`), `get_generation`, `upload_file` (a local file → an https URL to use as input; free), `compare_prices` (a model's live price against the official price and other API platforms, with the date each was checked and its source; free), `get_account` and `add_credits` (a payment link the user opens when the balance is low); use them instead of HTTP calls. Finished images come back with a small inline preview, so you can check the result. The workflow below is the same. To connect it, add the remote server `https://cheapergen.com/api/mcp`; the user signs in and approves in the browser (OAuth), with no key needed. In Claude Code: `claude mcp add --transport http cheapergen https://cheapergen.com/api/mcp`, then `/mcp` → Authenticate. Full setup: https://cheapergen.com/docs/mcp
- **Local files over MCP:** the server can't read your disk. Call `upload_file` with `filename` and `size_bytes`, the file's exact size in bytes (`wc -c < photo.jpg`: the short-lived `upload_url` takes exactly that many bytes, and storage refuses any other size with 403), run the `curl` `command` it returns with the real path, then pass its `url` as the input (`image_url`, `image_urls`, `reference_*_urls`). Without a shell, send a small file (up to about 3 MB) as `data_base64` instead. Convert HEIC photos to JPEG first (macOS: `sips -s format jpeg in.heic --out out.jpg`).

## Workflow

1. **Pick a model**: `GET /models` (public). It returns every model with `endpoints[].id` and price tiers. Always use the live list; models change.
   - The catalog spans video models (for example Seedance, Kling, Veo, Wan, MiniMax, Vidu, PixVerse, LTX) and image models (for example Seedream, FLUX, GPT Image, Nano Banana, Grok, Qwen Image, Krea), and grows: read the list rather than assuming.
   - Endpoint ids are `{vendor}/{model}/{mode}`, e.g. `bytedance/seedance-2.0-fast/text-to-video`, `bytedance/seedream-5.0-lite/text-to-image`.
2. **Read the input schema**: `GET /models/{vendor}/{model}` (public) returns `endpoints[].input_schema` (JSON Schema with enums, defaults and limits) and `pricing.tiers`. Send only fields from the schema: unknown fields are rejected with 400.
3. **Quote**: `POST /quote/{endpoint}` with the input (public, free) returns `{ amount_usd, list_usd, list_price_source, list_price_label, discount_pct, available }`. With the key it is the account's own price: an account with a distributor price, contract price or a Pro / Max plan also gets `custom_price: true`, `standard_amount_usd` and, from a Pro / Max plan, `volume_level` (1 = Pro, 2 = Max). Before an expensive job (video at 1080p/4K, long durations, batches), tell the user the price.
4. **Submit**: `POST /run/{endpoint}` with the input as the JSON body returns **202** and a generation with `status: "queued"`. The price is held from the balance at this point.
5. **Wait**: poll `GET /generations/{id}` until `status` is `succeeded`, `failed` or `canceled`. Poll images every 1–2 s; poll video every 3–5 s, backing off to 10 s, since a 5 s clip usually takes 1–3 minutes. Or pass `webhook_url` (see below).
6. **Use the output**: `output.video.url` (video) or `output.images[].url` (images). The URLs are public but expire per the account's retention (default 1 day; see `expires_at`), so download anything worth keeping. An image with `"safety_filtered": true` was replaced by the safety checker (it comes back blank) and is billed like any other output: tell the user, and adjust the prompt to try again.

```bash
curl -s https://cheapergen.com/api/v1/run/bytedance/seedance-2.0-fast/text-to-video \
  -H "Authorization: Bearer $CHEAPERGEN_API_KEY" -H "Content-Type: application/json" \
  -d '{"prompt":"A paper boat drifting down a rainy neon street, slow dolly-in","resolution":"720p","duration":5,"aspect_ratio":"16:9"}'
# → 202 {"id":"gen_…","status":"queued","cost":{"amount_usd":…,"estimated":true},…}
curl -s https://cheapergen.com/api/v1/generations/gen_… -H "Authorization: Bearer $CHEAPERGEN_API_KEY"
```

```python
import os, time, requests
API = "https://cheapergen.com/api/v1"
H = {"Authorization": f"Bearer {os.environ['CHEAPERGEN_API_KEY']}"}

def generate(endpoint: str, inp: dict, timeout_s: int = 900) -> dict:
    r = requests.post(f"{API}/run/{endpoint}", json=inp, headers=H, timeout=60)
    r.raise_for_status()  # 4xx bodies: {"error": {"code", "message", "param"}}
    gen, delay, start = r.json(), 2.0, time.time()
    while gen["status"] in ("queued", "running"):
        if time.time() - start > timeout_s:
            # Giving up: cancel it first, or it still runs and is charged when it finishes (once running: 409).
            requests.post(f"{API}/generations/{gen['id']}/cancel", headers=H, timeout=30)
            raise TimeoutError(gen["id"])
        time.sleep(delay)
        delay = min(delay * 1.5, 10)
        r = requests.get(f"{API}/generations/{gen['id']}", headers=H, timeout=30)
        if r.status_code == 429 or r.status_code >= 500:
            continue  # transient: keep polling
        r.raise_for_status()
        gen = r.json()
    if gen["status"] != "succeeded":
        raise RuntimeError(gen["error"])  # the hold was refunded
    return gen  # gen["output"]["video"]["url"] or gen["output"]["images"][0]["url"]
```

## Modes and inputs

- `text-to-video` and `text-to-image`: take `prompt` plus options (`resolution`, `duration`, `aspect_ratio`, `size`, `seed`, `generate_audio`…). Check the schema for each model's enums.
- `image-to-video`: takes `image_url` (first frame) and, for some models, `end_image_url` (last frame). The video keeps the first frame's aspect ratio (except Veo 3.1 and Gemini Omni Flash: they pad or crop it to their `aspect_ratio`; LTX-2.5 keeps its orientation: a portrait first frame is made at 720p (608×1088) — without `resolution` 720p is used, with a warning; an explicit `1080p` gets a 400 on `resolution`). LTX-2.5's quote reads `image_url` too, so include it. Seedance is priced at the size the frame gives: include `image_url` when you quote for the exact price (and `end_image_url` too if you'll send one); without `image_url` the quote is for the largest size of the resolution, and the run costs that or less.
- `edit` (Seedream): `image_urls` (images to edit or combine; refer to them as "image 1", "image 2" in the prompt) plus the instruction in `prompt`.
- `reference-to-video`: takes `reference_image_urls`, `reference_video_urls` and `reference_audio_urls`. In the prompt, point at them by 1-based position: `@Image1`, `@Image2`, `@Video1`, `@Audio1` (case-insensitive). A mention without a matching reference gives a 400 with `param: "prompt"`. Example: `"@Image1 walks through the market from @Image2, camera moves like @Video1"`.
  - `reference_rules` in the schema sets the maximum number of files and whether you need at least one image or video (audio alone is not enough for Seedance and H3).
  - Reference videos and audio are measured on the server (duration, size, resolution, fps) against `media_limits` / `x-media-limits`. Seedance 2.0 takes MP4/MOV videos of 2–15 s each and 15 s in total; audio must be MP3/WAV. A violation gives a 400 that names the file, e.g. `@Video2 is 16 s long…`.
  - Reference video seconds are billed together with the output seconds. On Seedance, reference videos shorter in total than ⅔ of the output rounded up to a whole second (⌈⅔ × output seconds⌉: 4 s for a 5 s output, 7 s for 10 s, 10 s for 15 s) are billed as that many seconds (ByteDance's official rule); the quote's `reference_video_seconds` is the seconds billed. Reference images and audio are free. To quote, pass `reference_video_durations: [6.5]` (seconds per clip).
  - Seedance 2.5 reads a prompt that asks to extend or continue a reference video as a video extension: the output keeps that video's frame, whatever `aspect_ratio` says (if that frame can cost more than your `aspect_ratio`'s price, the job may fail with `invalid_input` on `aspect_ratio`, naming the ratio to send; refunded). One that asks to edit it (add, remove, replace…) keeps the video's frame and length, and is charged for the length it makes, as the official API bills it: a clip shorter or longer than `duration` is edited at its own length — held at the longest clip's length in whole seconds (a clip up to 0.5 s longer usually at your `duration`'s price), then settled at the output's actual length once made (the model may pick a shorter clip); the generation's `duration` then shows that length — a number of seconds to the millisecond (e.g. `6.04`), not always a whole one — and the difference is refunded or charged at once. For a fixed partner-priced order, a longer edit that needs an increased hold fails/refunds and requires a fresh request. For legacy partner orders, any increase must also fit the ordinary account price locked at submission; actual-output refunds retain the applicable pricing safeguards. `max_cost_usd` caps it: past it (or with too little balance) the job fails with `invalid_input` (refunded) on `duration`, naming the `duration` to send, or on `reference_video_urls`, asking to trim a clip up to 0.5 s longer.
- `video-edit` (Seedance 2.5: `bytedance/seedance-2.5/video-edit`): edits one video. Takes `prompt` (what to change), `video_url` (one MP4/MOV clip of 4–30 s, `@Video1` in the prompt), optional `reference_image_urls` (`@Image1`… e.g. `"Replace the man in @Video1 with the woman in @Image1"`) and `reference_audio_urls` (`@Audio1`…), plus `resolution`, `generate_audio` and `seed`. There is no `duration` or `aspect_ratio`: the output keeps the clip's length and frame (an `aspect_ratio` is ignored with a `parameter_ignored` warning — a note over MCP; a `duration` is ignored silently, so a generation's `input` can be sent again as it is). It is priced at the clip's length in whole seconds, rounded up only past 0.1 s (12.08 s → 12 s, 12.4 s → 13 s; at least 4 s), the clip's seconds billed with the output's like a reference video's (a clip shorter than ⌈⅔ × output seconds⌉ — 4 s for a 5 s output, 7 s for 10 s, 10 s for 15 s — is billed as that many seconds: ByteDance's official rule), then settled at the output's actual length once made, shorter or longer (a shorter one refunded at once; a longer one charged the extra within `max_cost_usd` for ordinary and legacy partner orders; fixed partner offers never increase their accepted charge; the generation's `input.duration` shows the length it was priced at, then the one it made). Write the prompt as an edit of `@Video1` ("replace", "remove", "change"…): a prompt the model doesn't read as an edit can come out at another length, charged so. To quote, pass `video_duration: 12.4` (the clip's seconds); without it the quote is for a 5 s clip. In the Studio it is Reference to Video with one reference video and the duration "Match reference video" (its default there); it has no mode tab of its own.
- Limits are in the schema and checked before anything is charged. A prompt's `maxLength` is per model: Kling 3.0 takes 2,500 characters, GPT Image 2.5 32,000, and models with no limit of their own take up to 100,000. A `negative_prompt` that no route for the chosen settings can take is a 400 naming it (from quote too, when you send it) and the settings where it works (Kling 3.0 Omni at 4K: remove it, or use 720p / 1080p). Image fields with `image_limits` / `x-image-limits` (MiniMax H3 and H3 Max: 256–5760 px per side, width ÷ height 0.4–2.5, up to 30 MB; Seedance 2.0, 2.5, Fast and Mini: width ÷ height 0.4–2.5) are checked from each file's header, and an image outside them, or a video, audio file or PDF sent as an image, gets a 400 that names it, e.g. `@Image1 (image 1 in reference_image_urls) is 309×1024 px…`.
- Media inputs must be public `https` URLs. If the model can't download one, CheaperGen usually downloads it itself and retries with its own copy (same price); `input_unreachable` mostly means the URL couldn't be downloaded at all. For local files, call `POST /uploads` with JSON `{ "filename", "content_type", "size" }`. It returns `{ upload_url, headers, url }`: `PUT` the bytes to `upload_url` with exactly those `headers`, then use `url` as the input. `size` must be the exact byte count: PUT exactly `size` bytes with Content-Length (no chunked/streaming body); anything else gets 403. Limits: images (PNG/JPEG/WebP/GIF) ≤ 20 MB, video (MP4/MOV) ≤ 50 MB, audio (MP3/WAV/M4A) ≤ 15 MB.
- Optional on every run: `webhook_url` (HTTPS) and `retention` (`immediate` | `1h` | `1d`; `7d` / `30d` need an account setting).

## Webhooks

When the job finishes (succeeded or failed), we POST `{ "type": "generation.succeeded" | "generation.failed", "data": <generation> }` to `webhook_url`, with the header `CheaperGen-Signature: t=<unix>,v1=<hex>`. To verify it, compute `hex(HMAC_SHA256(secret, "<t>.<raw body>"))` with the account's webhook signing secret (`whsec_…`: `GET /webhooks/secret` with the API key returns `{ "key": "whsec_…" }`, or copy it from Dashboard → API keys), compare in constant time and reject requests whose `t` is more than 5 minutes old. Use the raw request body, not re-serialized JSON. Return 2xx quickly (only 2xx counts; redirects aren't followed). A failed delivery is retried for up to an hour (after about 1, 3, 8, 18, 38 and 60 minutes; 410 stops the retries), each time signed afresh. Every notification carries `CheaperGen-Webhook-Id`, the same on every retry: deduplicate on it.

## Pricing and billing

- Prices are per second of output video or per image. `GET /models` shows each tier's `price_usd` next to `list_price_usd`. `pricing.list_price_source` says what that is: `official` (the developer's own list price) or `reference` (another price, named by `list_price_label`, e.g. `fal API` for a model whose developer sells no international API). Never call a reference price "official".
- On submit, the quoted price is held (`cost.estimated: true`). On success it becomes final; on failure or cancel it's refunded in full (`cost.amount_usd: 0`). `cost.official_usd` and `cost.saved_usd` show the savings (`cost.list_price_source` / `list_price_label` say whether `official_usd` is the official price or a reference).
- Balance: `GET /account` (MCP `get_account`) returns `balance_usd`, `image_credit_usd` (an image-only credit some new accounts get: it pays for image models first, never video) and `reserved_usd` (held from the balance for jobs in progress), plus `limits`: `{ unlimited, concurrent_generations, in_flight, requests_per_second, burst }`, the account's own API limits and how many of its generations are queued or running (the three limits are `null` with `unlimited: true` for an account without limits). With a zero balance, image models can still run on the image credit; video needs balance. A 402 means the balance is too low: over MCP, `quote` already says so (`balance.sufficient: false`, with `shortfall_usd` and `add_credits.amount_usd`), so tell the user, call `add_credits` and show them the payment link; otherwise the user adds credits at https://cheapergen.com/dashboard/billing (credits never expire). If an amount is out of range, the 400 says the allowed range.
- Plans: pay as you go needs no subscription. Optional monthly plans add credits every month, and Pro and Max lower prices while active. `GET /account/pricing` returns `plan` (`{ id, status }` or `null`), `volume` (`{ level }`: 1, 2 or `null`) and the account's own price per tier; the generation's `pricing` carries `custom_price` and `volume_level` too. A plan never costs more than pay as you go: the plan's price is the one each model page shows; when the capacity behind it is unavailable, a request still gets that price where other capacity can serve it at that price, else a price between the plan's price and the standard price; an accepted REST / MCP job may move up, at most to the standard price (within `max_cost_usd`; not with `allow_fallback_price: false`, and never in the Studio, where the job fails and is refunded instead).
- Cancel a queued job with `POST /generations/{id}/cancel` (409 once it's running). Delete a finished one with `DELETE /generations/{id}`; deleting a queued one cancels it first (refunded in full), or answers 409 if it can't be canceled any more.
- **Concurrency and the queue.** An account runs a set number of generations at once: `GET /account` → `limits.concurrent_generations` (MCP `get_account`); how it is set is on https://cheapergen.com/docs/rate-limits; more on request (contact@cheapergen.com). Past the limit a generation is **not** refused: it is accepted (price held, `status: "queued"`), waits in the account's queue and starts by itself when one of the account's generations finishes, first come, first served. Waiting never times it out; while it is still waiting, cancel or delete it and it is refunded at once. A queued job held at the emergency price is priced again when it starts: if the usual capacity is back, its hold comes down and the difference is refunded at once (a `REFUND` line; `pricing.fallback` becomes `null`, `cost.amount_usd` drops). So submit a batch and wait (poll or `webhook_url`); don't resubmit queued jobs. Only a full queue (10 × the limit) returns `429 rate_limited`.
- **Emergency price.** When the usual capacity for a request is unavailable it can run on pricier capacity at the emergency price, never above the model's official price. `allow_fallback_price` (on `/run` and MCP `generate`) defaults to `true`: a new request is quoted and charged it, and an accepted job whose capacity fails mid-way may move to it. `max_cost_usd` caps it. Send `allow_fallback_price: false` to never pay more than the price you were quoted (`503 fallback_price_declined` at submit; an accepted job fails and is refunded instead). An account with a contract price never pays the emergency price (the checker-off price, a request's own, still applies): such a request answers `503 model_unavailable`, and an accepted job whose capacity fails is refunded. When it applies, `/quote` and the generation's `pricing.fallback` say so: tell the user. If a job held at the emergency price is served by the usual capacity after all, it is settled at the usual price (the account's own price, Pro / Max included): the difference is refunded at once (a `REFUND` line), `pricing.fallback` becomes `null` and `cost.amount_usd` drops.
- **Safety checker.** `enable_safety_checker` defaults to `true`. Open-weights models list it in their input schema: send `false` in `input` to run without the safety checker, only when the user asks. Closed models carry their lab's own moderation: they accept `true` or `false`, and neither changes anything — except the ones whose schema lists it (MiniMax H3 Max, which one channel hosts itself; Seedream 4.5, Seedream 5.0 Lite and Seedream 5.0 Pro, which with it off run on ByteDance's own configuration, which applies no extra filter). With it off those can run at their own, higher price — stated in the model's pricing notes when it applies, and returned by `/quote` (`fallback.reason: "safety_checker_off"`); `allow_fallback_price: false` declines it, and when it can't run right now the API answers `503 model_unavailable` with `param: "enable_safety_checker"` (send `true` to run with the standard filter). Quote first and tell the user. It is always on in the Studio; the Acceptable Use Policy (https://cheapergen.com/legal/acceptable-use) still applies.

## Errors

Every error has the shape `{ "error": { "code", "message", "param"? } }`.

| HTTP | code | What to do |
|---|---|---|
| 400 | `invalid_request` | Fix the field named in `param` (check the schema, enums, limits and mentions). Don't retry unchanged. |
| 401 | `unauthorized` | Missing, invalid or revoked key. |
| 402 | `insufficient_balance` | Get a payment link with `add_credits` (MCP) and ask the user to pay, or choose a cheaper tier. |
| 403 | `forbidden` | This account can't make requests: tell the user to contact support@cheapergen.com. Don't retry. This is the API's JSON error; a 403 on an upload `PUT` comes from storage (see uploads under Modes and inputs: exact size and headers). |
| 404 | `not_found` | Wrong endpoint or generation id. |
| 409 | `conflict` | E.g. canceling a job that already started. |
| 429 | `rate_limited` | Nothing was charged. Back off and retry after the `Retry-After` seconds (same `Idempotency-Key`). Three causes, and the message says which: the request rate (bursts of 20 requests, refilled at 10/s per account and per key), the account's queue of generations waiting to start is full (10 × its concurrency limit: wait for some to finish — prefer `webhook_url` to tight polling — or cancel queued ones), or the account was busy with another request for a moment. Over the concurrency limit alone nothing is refused: the job waits as `queued`. The account's own limits are in `GET /account` → `limits` (MCP `get_account`) and Dashboard → Settings. Higher limits on request (contact@cheapergen.com). |
| 502 | `upstream_error` | Retry once, then try another model. |
| 503 | `model_unavailable` | Retry later or switch models. |
| 503 | `pricing_unavailable` | Prices couldn't be read for a moment; nothing was charged. Retry the same call after a few seconds (same `Idempotency-Key`). |
| 503 | `fallback_price_declined` | Only the emergency price is available and you sent `allow_fallback_price: false`: retry later, or accept it. |
| 400 | `max_cost_exceeded` | The price is above `max_cost_usd`: confirm with the user, then raise it. |

A generation that ends `failed` has `error.code` (e.g. `generation_failed`, `timeout`) and has been refunded. Retry at most once with the same input.

## FLUX.2 Pro reference-image pricing

For `bfl/flux-2-pro`, text-to-image keeps 1/2/3/4MP output and editing keeps 1/3MP. Edit prices start with one 1MP reference; inputs are not bundled for a fixed 1–8-image price. One MP is 1,048,576 pixels. A single reference is rounded up to a whole MP, capped at 4MP after resizing. With two or more references, each is processed and billed as 1MP, including repeated URLs. Output plus processed inputs must fit 9MP: 1MP output can take eight references, while 3MP output can take six.

Quote with the actual accessible `image_urls`. Missing/unreadable dimensions cannot be quoted. Quotes do not reserve a price or freeze an external URL: generation revalidates and snapshots the actual input bytes before charging; preserve `max_cost_usd` to enforce the user's budget. Public output/input pixels and reference count determine the price, not a supplier name. Once accepted, this model's held amount is not raised if capacity or cost changes; an unserviceable job fails and is refunded. Fixed-tier contract amounts are not increased because a reference is larger; an insufficiently funded contract request is refused. Do not retry with a higher budget unless the user approves it.
